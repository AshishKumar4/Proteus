## 3. Does the self-evolution loop implement GEPA?

The ALGORITHM, yes. `core/src/evolution/gepa/engine.ts` is the paper's loop:
seed scored on the full eval set, a Pareto-front pool with per-instance
dominance weighting for parent selection, reflective mutation from
per-instance score plus natural-language feedback traces (`mutate.ts`), the
Appendix-F Merge operator on complementary pairs (`merge.ts`), and budget
accounting by metric call.

The EVIDENCE, no. What the automatic lane optimises is a prompt SECTION's
text, and its metric is not a rollout: `renderSectionScorePrompt`
(`control.ts`) asks one judge model "given this recorded response, would
this wording have produced one at least this good?" Both GEPA's minibatch
feedback and the "held-out trials" that promote a winner
(`runPromptSectionTrials`) are that same counterfactual guess on different
recorded turns. A chat turn cannot be replayed against the same user, so
nothing here measures behaviour; it measures a judge's opinion of wording.
Promotion is by win rate over three trials of that opinion.

The lane that DID roll out (`runScaffold`) optimised `scaffold/agent.js`,
which the chat turn never executes. It is off the tick as of `ba6d55f8`.

Has it ever run automatically in production? The trigger chain is:
`engine.reviewTurn` grades each turn (thumbs, else one `tiny`-tier
classifier call on your next message, else the execution verdict — a
failed last tool call grades as `corrected`); three ungraded negatives
open a refinement request; the refiner is a temporary agent that reads
`context_ref` files. Until `ba6d55f8` those refs named files that do not
exist in a standard workspace, so every refinement refused before it
started. The prompt-section GEPA lane needs an eval split with both
accepted and negative labelled turns; check `gepa_runs` in the hardy-stone
DO to see whether it ever completed one there. Nobody had.

Honest verdict: GEPA is implemented as a search procedure over a weak
proxy metric, gated by a promotion rule on the same proxy. Whether that is
worth its judge calls is unmeasured. Decide with a number: count promoted
sections in `prompt_section_versions` across your workspaces before
spending more on it.

## 5. The defect classes, and what "properly addressed" needs

Found in one day; each with a fix in this branch and the class behind it.

1. **Seams tested only with fakes.** The refiner test asserted the string
   `AGENTS.md` against a scripted refiner; the port that refuses absent paths
   was tested with its own fake. `createTool` admitted anything; the sandbox
   that would reject it was never in the same test. The Devbox alarm sweep
   ran only inside a hook that never fires while the container sleeps.
   Fixed cases now cross the real seam (refiner ↔ real VFS, crafted source ↔
   real workerd). The class needs a rule: a test of a producer/consumer pair
   builds BOTH sides from production code or says why it cannot.
2. **Prompt-driven behaviour with no measurement.** The nudges. Gone. The
   rule: a prompt sentence that steers behaviour carries the measurement
   that justified it or does not land.
3. **Platform limits assumed, not measured.** Facets share the root's
   isolate; a swarm node ran an npm install in it. `gate:platform` already
   refuses an unnamed number; the guard names `worker.isolate.memory`.
4. **Ten-subsystem commits.** `7ba56550` landed the refiner bug and nine
   other subsystems in one commit, each green in isolation, integration
   unowned. This branch is six commits, one concern each. Keep it that way.
5. **Machinery that spends money on nothing.** The scaffold GEPA lane
   (569k input tokens in one workspace on an artifact the turn never ran).
   Off. Not yet audited with the same question — "who consumes this lane's
   output?" — sleep-time updates, curriculum proposals, alternate takes,
   shadow trials, advisor reviews. Do that audit before anything else in
   §6; each is a lane with model calls and a mocked test island.
6. **Gates that check text and shapes, not behaviour.** Prompt-byte
   ceilings, manifest sets, constructor-signature string assertions. They
   stay (weakening a gate is forbidden), but they are not evidence that a
   turn works. The workerd sandbox test is the pattern to copy: the real
   thing, exercised.
